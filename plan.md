# TRACE v5 Plan: Full / Normal / Compact

## 1. Цель
Сделать TRACE-отчет управляемым по детализации без потери основного назначения трассировки:

- показать фактический след выполнения алгоритма,
- позволить LLM сопоставить след с исходным кодом,
- объяснить причину поведения,
- определить оптимальные точки внесения изменений.

Ключевой принцип: пользователь и модель всегда должны понимать, что именно скрыто в режиме не `full`, и как запросить более глубокий отчет.

## 2. Режимы TRACE (зафиксированная семантика)

### `full`
Когда использовать:

- финальный разбор причины поведения,
- верификация сложной ветвистости,
- выбор точной строки/точек для правок.

Свойства:

- максимально полный след,
- минимальная фильтрация,
- максимум строк и шума,
- режим "доказательной полноты".

### `normal`
Когда использовать:

- режим по умолчанию для ежедневной работы,
- анализ логики без перегруза.

Свойства:

- сохраняет причинно-следственную цепочку и ключевые вызовы,
- убирает низкоинформативный шум,
- обязательно показывает метрики скрытия.

### `compact`
Когда использовать:

- быстрый triage,
- короткий отчет для сравнения прогонов/обсуждения.

Свойства:

- агрессивное сжатие,
- быстро показывает основные узлы,
- меньше деталей для точечного изменения,
- обязательно показывает, что и сколько скрыто.

## 3. Обязательная прозрачность потерь
Для `normal` и `compact` добавить явную секцию покрытия, например:

`=== TRACE COVERAGE ===`

Минимальный набор метрик:

- `mode`,
- `events_total`,
- `events_shown_execution_flow`,
- `events_hidden_execution_flow`,
- `call_map_total_entries`,
- `call_map_shown_entries`,
- `call_map_hidden_entries`,
- `modules_total_events`,
- `modules_shown_events`,
- `modules_hidden_events`,
- причины скрытия с количеством:
- `structural_noise`,
- `control_leaf_noise`,
- `terminal_trivial`,
- `tiny_leaf`,
- `collapsed_repeats`,
- `collapsed_callbacks`,
- `threshold_hidden`.

Требование: пользователь и модель по этому блоку должны видеть, что скрыто, а не только факт "сжатия".

## 4. Требование к заголовкам и промпту модели

### Заголовок отчета
Режим TRACE обязательно включать в заголовок:

- `=== TRACE [FULL] ===`
- `=== TRACE [NORMAL] ===`
- `=== TRACE [COMPACT] ===`

### Промпт модели
Заголовок промпта также должен включать режим:

- `=== ПРОМПТ ДЛЯ МОДЕЛИ (TRACE FULL) ===`
- `=== ПРОМПТ ДЛЯ МОДЕЛИ (TRACE NORMAL) ===`
- `=== ПРОМПТ ДЛЯ МОДЕЛИ (TRACE COMPACT) ===`

В `NORMAL` и `COMPACT` обязательная строка:

- "Если данных недостаточно для уверенного вывода, запроси этот же отчет в `TRACE FULL` (с теми же фильтрами `entry/main-block`, если они использовались)."

В `FULL` обязательная строка:

- "Это максимально полный след; при локальной диагностике можно дополнительно запросить тот же отчет с `entry/main-block`."

## 5. Решение по "Умное сжатие"
Отдельный переключатель `Умное сжатие` в TRACE больше не нужен как пользовательская опция, потому что его роль покрывают режимы детализации.

Решение:

- GUI: убрать чекбокс `Умное сжатие`,
- вместо него добавить выбор `Детализация TRACE: Full / Normal / Compact`.

Совместимость:

- CLI-опцию `--no-compact` сохранить как legacy-алиас (например, маппинг в `trace-detail=full`), пометить deprecated в help.

## 6. Детальный бриф реализации (для следующего агента)

### 6.1. API и конфигурация
Изменить pipeline так, чтобы режим детализации передавался явно:

- `process_pff(..., trace_detail=...)`,
- `ReportGenerator(..., trace_detail=...)`,
- все TRACE-строители используют `trace_detail`.

Создать единый enum/набор констант:

- `TRACE_FULL`,
- `TRACE_NORMAL`,
- `TRACE_COMPACT`.

### 6.2. Поведение фильтров по режимам
Реализовать без хардкода модулей/расширений.

`full`:

- отключить/минимизировать фильтрацию,
- не обрезать `CALL MAP`,
- не скрывать мелкие блоки в `MODULES`,
- по возможности отключить свертки, которые скрывают фактический след.

`normal`:

- текущая адаптивная логика (threshold по распределению budget),
- умеренная фильтрация и ограничение `CALL MAP`,
- секция покрытия обязательна.

`compact`:

- более высокий адаптивный порог,
- более строгий лимит `CALL MAP`,
- более агрессивная фильтрация/коллапс,
- секция покрытия обязательна.

### 6.3. Формат отчета
В TRACE-отчете:

- включить режим в заголовок,
- добавить `TRACE COVERAGE`,
- затем секции `EXECUTION FLOW`, `CALL MAP`, `MODULES`,
- при обрезке `CALL MAP` печатать строку вида:
- `... ещё N строк с меньшим Budget скрыто`.

### 6.4. Промпт для LLM
Сделать генерацию TRACE-промпта параметризуемой по `trace_detail`.

Обязательно:

- упоминание текущего режима,
- явная инструкция, что можно запросить более глубокий отчет (`TRACE FULL`).

### 6.5. CLI
Добавить:

- `--trace-detail {full,normal,compact}`.

Поведение:

- default: `normal`,
- `--mode PERF` игнорирует `trace-detail` (или валидно сообщает об игноре),
- `--no-compact` оставить как deprecated-алиас в `full`.

## 7. Критерии приемки

- режимы `full/normal/compact` реализованы и документированы,
- режим TRACE указан в заголовке отчета и в заголовке промпта модели,
- модель получает явную инструкцию, что может запросить более глубокий отчет,
- для не-full режимов видна прозрачная отчетность о скрытых данных,
- переключатель `Умное сжатие` исключен из GUI как отдельная сущность (или строго legacy),
- поведение универсально и не зависит от имен конкретных модулей/расширений.
