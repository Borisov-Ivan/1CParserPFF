# 1CParserPFF

Проект для парсинга и анализа файлов замеров производительности 1С (PFF).

## Описание

`1CParserPFF` — это инструмент для преобразования файлов замеров производительности 1С (`.pff`) в человекочитаемые форматы, удобные для анализа разработчиками и LLM (Large Language Models).

Парсер поддерживает два основных режима работы:

1.  **TRACE (Трассировка)**: Полный хронологический лог выполнения с восстановлением иерархии вызовов. Отвечает на вопрос "Что произошло?".
2.  **PERF (Производительность)**: Анализ узких мест (hotspots) и дерево критического пути. Отвечает на вопрос "Почему медленно?".

## Возможности

*   **Восстановление контекста**: Автоматически определяет, где выполняется код (Клиент, Сервер, вызов Сервера с Клиента).
*   **Эвристическая реконструкция стека**: Для замеров формата 2b/2c (где нет явного уровня вложенности) строит дерево вызовов на основе анализа кода и бюджета времени (Total - Pure).
*   **Свёртка шума**:
    *   Сворачивает длинные цепочки асинхронных колбэков (`ВыполнитьОбработкуОповещения` и т.п.).
    *   Скрывает тривиальные процедуры и структурный шум (`КонецЕсли`, `КонецЦикла`).
    *   Объединяет повторяющиеся строки кода.
*   **LLM-Ready**: Генерирует промпты для языковых моделей в начале отчёта, объясняя структуру данных.

## Установка

Проект не требует внешних зависимостей (использует стандартную библиотеку Python 3).

```bash
git clone https://github.com/your-username/1CParserPFF.git
cd 1CParserPFF
```

## Использование

Запуск из командной строки:

```bash
python src/pff_parser.py <путь_к_файлу.pff> [путь_к_отчету.txt] [опции]
```

### Примеры

**Генерация TRACE (по умолчанию):**
```bash
python src/pff_parser.py my_trace.pff
```

**Генерация PERF (анализ производительности):**
```bash
python src/pff_parser.py my_trace.pff --mode PERF
```

**Фильтрация по порогу времени (например, скрыть всё быстрее 10мс):**
```bash
python src/pff_parser.py my_trace.pff --threshold 10
```

### Опции

*   `--mode {TRACE,PERF}`: Режим работы (по умолчанию `TRACE`).
*   `--threshold N`: Порог значимости в миллисекундах (по умолчанию 1% от общего времени).
*   `--entry "Module:Line"`: Фильтрация по точке входа (показать только вызовы, проходящие через эту строку).
*   `--main-block N`: Анализировать только указанный блок замера (сеанс).
*   `--no-context`: Не показывать контекст выполнения (C/S).
*   `--no-compact`: Отключить компактный вывод (показывать полные имена модулей везде).

## Форматы отчетов

### TRACE v4
Содержит секции:
1.  **EXECUTION FLOW**: Хронологическое дерево вызовов.
    *   `[C→S]` — вызов сервера с клиента.
    *   `[Self: 529ms]` — чистое время выполнения в данной строке (если значительно).
    *   `⤷ [колбэки ×3: ...]` — свернутые цепочки обработчиков оповещений.
2.  **CALL MAP**: Список строк с наибольшим "бюджетом" (временем, ушедшим во вложенные вызовы).
3.  **MODULES**: Детальная статистика по модулям и строкам кода.

### PERF v4
Содержит секции:
1.  **TOP ISSUES**: Топ проблем производительности, сгруппированных по смыслу (HTTP, SQL, Бизнес-логика). Для каждой проблемы строится цепочка вызовов от корня.
2.  **HOTSPOTS**: Список самых "тяжелых" строк кода по чистому времени (Self time).

## Сборка портируемого exe

Для получения одного самодостаточного файла `1CParserPFF.exe` без зависимостей:

```bash
pip install pyinstaller
python build/build.py
```

Результат: `dist/1CParserPFF.exe` — можно копировать на любой Windows-ПК и запускать без Python.
