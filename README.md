# 1CParserPFF

Парсер файлов замеров производительности 1С:Предприятие (формат `.pff`).

**Что такое PFF:**

- Файлы `.pff` создаются платформой 1С при включенном замере производительности (меню **Сервис → Замер производительности** или форма **"Анализ замеров"** в конфигурации).
- PFF — это текстовый файл со структурированными данными: какие модули выполнялись, на каких строках, сколько времени, в каком контексте (клиент/сервер).
- Стандартная форма "Анализ замеров" показывает только сводную статистику по модулям. Этот парсер извлекает **полную хронологию выполнения** с причинно-следственными связями и точной локализацией узких мест.

**Два режима анализа:**

- **TRACE** — для отладки логики: что за чем вызывалось, где серверный вызов, откуда пришёл колбэк, какая цепочка привела к ошибке.
- **PERF** — для поиска узких мест: топ-10 медленных операций, горячие точки, где именно тормозит (модуль + строка).

## Зачем нужен парсер (примеры из практики 1С)

- **Найти, почему тормозит проведение документа:** замерили проведение → PERF показал, что 80% времени в запросе на строке 245 модуля `ДокументыСервер` → оптимизировали индексы.
- **Разобраться в цепочке серверных вызовов:** сложная форма с 5 серверными вызовами → TRACE показал полную последовательность: какая кнопка → какой обработчик → какой вызов сервера → какой модуль → какой метод.
- **Понять, откуда вызывается проблемная функция:** в логах ошибка из `РаботаСФайламиСлужебный.ПроверитьДоступ()` → TRACE показал полную цепочку от формы через 3 модуля.
- **Найти лишние обращения к серверу:** открытие справочника тормозит → TRACE показал 12 серверных вызовов вместо ожидаемых 2 → нашли лишние `ПолучитьРеквизитыСервера()`.
- **Анализ работы расширений:** замер показал вызовы кода расширения → отчёт чётко разделил основную конфигурацию и код расширения с указанием модулей.

## Начало работы

### Способ 1: Готовый EXE (рекомендуется)

Не требует установки Python.

1. Скачайте `1CParserPFF.exe` из [Releases](https://github.com/Borisov-Ivan/1CParserPFF/releases)
2. Запустите двойным кликом
3. Выберите файл `.pff` → выберите режим (TRACE или PERF) → нажмите "Сформировать отчёт"
4. Результат отобразится в окне, сохраните через кнопку "Сохранить в файл"

### Способ 2: Через Python (для продвинутых)

Требует Python 3.7+ (внешние зависимости не нужны).

**GUI:**

```bash
python src/pff_parser_gui.py
```

**CLI (для автоматизации/скриптов):**

```bash
# TRACE compact (быстрый обзор сценария)
python src/pff_parser.py замер.pff --mode TRACE --trace-detail compact

# TRACE full (подробная трассировка)
python src/pff_parser.py замер.pff --mode TRACE --trace-detail full

# PERF (поиск узких мест, порог 10 мс)
python src/pff_parser.py замер.pff --mode PERF --threshold 10
```

Полный список опций CLI — в [docs/README.md](docs/README.md).

## Что получится на выходе

Пример фрагмента отчёта **TRACE compact** (реальный замер):

```
=== EXECUTION FLOW ===
?1534 [C→S] M01:32 | Результат = ргПроверитьПолучениеХэшаНаСервере();
  ?1354 [S] M01:47 | Хеш = ргСервисКриптографииCryptoAPI.ВычислитьХешГОСТ2012(...);
    ?1303 [S] M02:4363 | ОбъектКомпоненты = ргСервисКриптографии...ОбъектВнешнейКомпоненты();
      ?761 [S] M04:6468 | РезультатПроверки = ВнешниеКомпонентыСлужебный.ПроверитьПодключение(...);
      ?110 [S] M07:92 | Результат = Запрос.Выполнить();
```

**Что видно:**

- `[C→S]` — вызов с клиента на сервер
- `[S]` — серверное выполнение
- `M01:32` — модуль M01 (расшифровка в секции MODULES MAP), строка 32
- `?1534` — ссылка на событие с ID 1534 в исходном замере (для верификации)
- Отступы показывают вложенность вызовов

Расшифровка модулей:

```
M01: [X1] Обработка.НастройкаПрограммы.Форма.НастройкиЭП.Форма
M02: [X1] ОМ.ргСервисКриптографииCryptoAPI
M04: ОМ.ОбщегоНазначения
X1: ргОблачныеПодписиKonturCryptoAPI (расширение)
```

## Режимы: когда какой использовать

| Задача | Режим | Детализация |
|--------|-------|-------------|
| Понять **что происходит** (логика, последовательность вызовов) | **TRACE** | `compact` для быстрого обзора, `full` для подробной трассировки |
| Найти **где тормозит** (узкие места, медленные операции) | **PERF** | Установить порог (например, 10 мс) для фильтрации незначительных операций |
| Разобраться в цепочке колбэков или серверных вызовов | **TRACE** | `compact` обычно достаточно |
| Найти медленный запрос или вызов внешней компоненты | **PERF** | Порог 5-10 мс |
| Подготовить данные для анализа ИИ-моделью (Claude, GPT) | **TRACE** | `compact` (меньше токенов) |

## Автономный разбор `.pff` агентом

Если задача связана с разбором замера производительности 1С в формате `.pff`, агент должен запускать парсер автоматически.
- Для вопросов "что происходило", "откуда вызов", "какая цепочка": `--mode TRACE --trace-detail compact`.
- Для вопросов "почему медленно", "где узкое место": `--mode PERF --threshold 10`.
- Если `TRACE compact` не даёт достаточно контекста для root-cause, повторить запуск с `--trace-detail full`.
- Порог `--threshold` влияет только на `PERF` и игнорируется в `TRACE`.
- Deprecated-опции `--no-compact` и `--no-expand-modules` использовать только для обратной совместимости.

Подробный workflow интеграции — в разделе «Интеграция в AGENTS.md: автономный выбор TRACE/PERF» в [docs/README.md](docs/README.md).
