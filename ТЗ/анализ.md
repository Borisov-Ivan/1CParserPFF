# Расширенный критический анализ формата TRACE v6

Независимое исследование замеров из `examples/` (файл «Проверка расчета хэша»).
Цель — выявить все проблемы текущего формата TRACE v6 с фокусом на эффективность использования токенов, устранение избыточности и подготовку ТЗ на доработку.

## 3. ГЛАВНЫЕ ПРОБЛЕМЫ (Token Eaters) — количественный анализ

### 3.1. [CRITICAL] EventID-ссылки — 30-36% объёма файла

**Что происходит:** Каждая строка данных в EXECUTION FLOW, CALL MAP и MODULES несёт полную ссылку вида:
```
[FACT E01534 -> ргОблачныеПодписиKonturCryptoAPI Обработка.НастройкаПрограммы.Форма.НастройкиЭлектронныхПодписей.Форма:32]
```
Это **~125 символов** на одну ссылку. В FULL файле 407 таких ссылок = **29 367 символов** чистого overhead.

**Почему это проблема:**
- Одна треть всего файла — это повторяющиеся префиксы с полными путями модулей.
- Ссылка содержит полный путь модуля, который уже указан в заголовке секции MODULES и часто дублируется в самой строке.
- LLM тратит контекстное окно на парсинг одного и того же пути `ргОблачныеПодписиKonturCryptoAPI ОбщийМодуль.ргСервисКриптографииCryptoAPI.Модуль` по 20-30 раз.

**Сравнение:**
| Текущий формат | Целевой формат | Экономия |
|----------------|----------------|----------|
| `[FACT E01534 -> ргОблачныеПодписиKonturCryptoAPI Обработка.НастройкаПрограммы.Форма.НастройкиЭлектронныхПодписей.Форма:32]` (125 сим) | `#1534` (5 сим) | **96%** |
| `[INFERRED E01303 -> ргОблачныеПодписиKonturCryptoAPI ОбщийМодуль.ргСервисКриптографииCryptoAPI.Модуль:4363]` (107 сим) | `?1303` (5 сим) | **95%** |

### 3.2. [CRITICAL] Повторение имён модулей

| Паттерн | FULL | NORMAL | COMPACT |
|---------|------|--------|---------|
| `ОбщийМодуль.` (повторений) | 392 | 161 | 68 |
| `ргОблачныеПодписиKonturCryptoAPI` (повторений) | 56 | 52 | 39 |
| `Обработка.НастройкаПрограммы.Форма.НастройкиЭлектронныхПодписей.Форма` (повторений) | 19 | 19 | 16 |

Строка `ргОблачныеПодписиKonturCryptoAPI` — 33 символа. При 56 повторениях в FULL это **1 848 символов** только на имя расширения. А полное имя модуля `ргОблачныеПодписиKonturCryptoAPI ОбщийМодуль.ргСервисКриптографииCryptoAPI.Модуль` — это 82 символа, и оно появляется в 3 разных секциях по несколько раз.

### 3.3. [HIGH] Тройное дублирование событий между секциями

Одно и то же событие (например, E01534) упоминается:
1. **EXECUTION FLOW** — с полной ссылкой + код строки + время
2. **CALL MAP** — с полной ссылкой + код строки + Budget
3. **MODULES** — с полной ссылкой + код строки + Total + Pure

Каждое появление несёт полный путь модуля. Для топ-события E01534 это ~375 символов суммарно на ОДНО событие в трёх секциях.

### 3.4. [HIGH] Строки `[свёрнуто по threshold]` — информационный мусор

| Режим   | Таких строк | Символов впустую |
|---------|-------------|------------------|
| FULL    | 33          | ~2 310           |
| NORMAL  | 40          | ~2 800           |
| COMPACT | **29**      | **~2 030**       |

**Критическая проблема:** в COMPACT режиме (назначение — «быстрый triage») 29 строк занимают место только чтобы сообщить «тут ничего нет». Пример из COMPACT:
```
  [S] Func (:144-380) Total: 2.16ms  [свёрнуто по threshold]
  [S] Func (:411-420) Total: 2.18ms  [свёрнуто по threshold]
  [S] Func (:455-642) Total: 1.95ms  [свёрнуто по threshold]
  ...ещё 12 таких строк для одного модуля ОбщегоНазначения
```
Это информация о том, что 15 функций скрыты — но факт скрытия **уже зафиксирован** в TRACE COVERAGE (`threshold_hidden=1506`). Повторение поштучно бессмысленно.

### 3.5. [HIGH] Заголовки модулей в секции MODULES

Каждый заголовок модуля — полноименная строка:
```
--- B0 [Сервер] [Ext:ргОблачныеПодписиKonturCryptoAPI] ОбщийМодуль.ргСервисКриптографииCryptoAPI.Модуль ---
```
Это ~105 символов. В FULL таких 37 штук = **2 835 символов**.

С алиасами: `--- B0 [S] X1:M12 ---` = ~22 символа. Экономия: **79%**.

### 3.6. [MEDIUM] Перекрёстные ссылки `-> see:` в CALL MAP

Строки вида:
```
-> [INFERRED] see: ргСервисКриптографииCryptoAPI [S] Func(:4357-4423) [Total: 1528.05ms]
```
В FULL: 13 штук на 1 053 символа. Эти строки дублируют информацию из MODULES (модуль + диапазон строк) и содержат время (Total), которое в TRACE режиме декларируется как неуместное.

### 3.7. [MEDIUM] Временные значения в TRACE-режиме

| Режим   | Паттернов с временем |
|---------|---------------------|
| FULL    | 544                 |
| NORMAL  | 264                 |
| COMPACT | 124                 |

TRACE декларирует: «временные оценки — зона PERF, не TRACE». При этом каждая строка MODULES содержит `Total` и `Pure`, каждая строка CALL MAP — `Budget`, каждая строка FLOW — `[Self: Xms]` или `[Xms / Yms]`.

Это не просто нарушение принципа — это **сотни токенов** времени в каждом отчёте. В FULL 544 паттерна × ~10 символов среднем = ~5 440 символов.

### 3.8. [MEDIUM] Метки FACT/INFERRED — избыточная гранулярность

| Режим   | INFERRED | FACT |
|---------|----------|------|
| FULL    | 58       | 365  |
| NORMAL  | 33       | 148  |
| COMPACT | 20       | 63   |

**Проблема:** В EXECUTION FLOW почти всё INFERRED (что логично — это эвристическая реконструкция). В MODULES почти всё FACT (данные из трассы). Тип метки **предсказуем по секции**.

Достаточно указать тип по умолчанию в заголовке секции и отмечать только исключения.

## 4. СТРУКТУРНЫЕ ПРОБЛЕМЫ

### 4.1. CALL MAP дублирует EXECUTION FLOW

CALL MAP и EXECUTION FLOW показывают одни и те же события. Разница:
- FLOW: иерархия вызовов с отступами + время
- CALL MAP: плоский список, отсортированный по Budget + ссылки `-> see:`

**Вопрос:** нужны ли обе секции? CALL MAP — это фактически FLOW, отсортированный по Budget, с добавлением `-> see:` ссылок. Для задач TRACE (анализ логики, не производительности) сортировка по Budget не имеет смысла.

**Рекомендация:** В TRACE-режиме CALL MAP либо убрать, либо радикально упростить до индекса навигации (список #ID без Budget и ссылок).

### 4.2. MODULES содержит нерелевантные модули

Даже в COMPACT, секция MODULES показывает:
- `ОбщийОбработчикОжиданияВызовСервера` — фоновый обработчик ожидания
- `РаботаСУведомлениями` — проверка уведомлений
- `Сотрудники` — подсистема сотрудников

Эти модули **не имеют отношения к сценарию** (проверка расчёта хэша). Они попали в замер потому, что обработчик ожидания сработал во время измерения. В COMPACT они должны быть отсечены.

### 4.3. TRACE COVERAGE — формат неоптимален

Текущий формат:
```
events_total=1535 events_shown=43 events_hidden=1492
call_map_total_entries=30 call_map_shown_entries=30 call_map_hidden_entries=0
modules_total_events=1535 modules_shown_events=334 modules_hidden_events=1201
structural_noise=202
control_leaf_noise=108
...
```
Ключ-значение в одну строку через пробел — трудночитаемо и неоптимально для токенов. Можно сжать в компактную таблицу.

### 4.4. TRACE META — утечка служебных параметров

В META публикуются:
```
flow_threshold_ms: 0.9546
modules_threshold_ms: 0.1000
flags: show_context=True, expand_module_names=True, collapse_repeats_min=999999, collapse_callbacks_min=999999
```
Это **внутренние параметры алгоритма**, не несущие ценности для анализа. Пользователю/модели не нужно знать точные пороги в мс — это зона `TRACE REPRODUCE`.

## 5. СРАВНЕНИЕ С ПРЕДЫДУЩИМ АНАЛИЗОМ (ТЗ\анализ.md v1)

### Что было верно определено ранее:
1. Полные имена модулей — основной пожиратель токенов ✓
2. Синтаксис EventID/INFERRED избыточен ✓
3. Метрики времени в TRACE дублируют PERF ✓
4. Нужна таблица алиасов модулей ✓

### Что было НЕДООЦЕНЕНО или ПРОПУЩЕНО:

| Проблема | Предыдущий анализ | Наш анализ |
|----------|-------------------|------------|
| **Количественная оценка** | «30-40% объёма» | Точно: EventID-ссылки = **30-36%** от файла. Но это лишь часть — суммарно overhead ~55-60% |
| **Тройное дублирование событий** | Упомянуто поверхностно | Каждое событие описано 3 раза (FLOW + CALL MAP + MODULES) с полным путём |
| **Строки `[свёрнуто по threshold]`** | Не упомянуто | 29-40 строк мусора во всех режимах, включая COMPACT |
| **CALL MAP дублирует FLOW** | «Убрать время из CALL MAP» | CALL MAP в TRACE-режиме **концептуально избыточна** — это FLOW, отсортированный по Budget |
| **Фоновые модули в COMPACT** | «Побочные ветки свёрнуты» | Не свёрнуты — Сотрудники, Уведомления, ВстроеннаяПочта остаются в MODULES даже в COMPACT |
| **TRACE META утечка** | «Скрыть пороги» | Не просто скрыть — `flow_threshold_ms`, `modules_threshold_ms`, `flags` целиком не нужны в отчёте |
| **Целевой размер COMPACT** | 260 строк «удобно для первого взгляда» | 260 строк — это **не** быстрый triage. Цель: **60-80 строк** |
| **Формат TRACE COVERAGE** | «7 категорий информативны, обязательны» | Формат неоптимален: key=value через пробел, можно сжать вдвое |
| **FACT/INFERRED побуквенно** | «Оставить, оптимизировать представление» | Тип предсказуем по секции. Не нужен на каждой строке — достаточно default + exceptions |

На основе анализа формулирую целевые ограничения:

| Метрика | FULL | NORMAL | COMPACT |

## 7. РЕКОМЕНДАЦИИ (упорядочены по impact)

### R1. [CRITICAL] Таблица алиасов модулей (MODULES MAP)

Новая обязательная секция перед EXECUTION FLOW:
```
=== MODULES MAP ===
M01: [X1] Обработка.НастройкаПрограммы.Форма.НастройкиЭлектронныхПодписей.Форма
M02: [X1] ОМ.ргСервисКриптографииCryptoAPI
M03: [X1] ОМ.ргСервисКриптографииОбщегоНазначения
M04: ОМ.ОбщегоНазначения
M05: ОМ.ВнешниеКомпонентыСлужебный
...
X1: ргОблачныеПодписиKonturCryptoAPI
```
- `ОМ.` = сокращение для `ОбщийМодуль.` (стандартный тип, экономия ~10 символов каждый раз)
- `X1` = алиас расширения
- Далее в тексте используется `M01:32` вместо полного пути

### R2. [CRITICAL] Компактные ссылки EventID

Вместо:
```
[FACT E01534 -> ргОблачныеПодписиKonturCryptoAPI Обработка...Форма:32]
```
Использовать:
```
#1534
```
- `#` = факт (default для MODULES и CALL MAP)
- `?` = эвристика (default для EXECUTION FLOW)
- Путь модуля не нужен в ссылке — он восстанавливается из MODULES MAP по EventID

### R3. [HIGH] Убрать `[свёрнуто по threshold]` строки

В COMPACT и NORMAL: полностью убрать эти строки. Информация о скрытии уже есть в TRACE COVERAGE. Если модуль состоит только из скрытых функций — не показывать модуль вообще.

В FULL: заменить серию из N скрытых функций одной строкой-сводкой:
```
  [ещё 15 функций, Total < 0.1ms]
```

### R4. [HIGH] Переосмыслить CALL MAP в TRACE-режиме

Варианты:
- **A.** Убрать CALL MAP из TRACE полностью (оставить только в PERF)
- **B.** Заменить на компактный навигационный индекс без Budget:
```
=== CALL INDEX ===
#1534 → M01:32 → #1354 M01:47 → #1303 M02:4363 → #1293 M03:35 → #761 M04:6468
```
Это вся цепочка вызовов в одну строку вместо 30 строк CALL MAP.

**Предпочтительный вариант: B** — навигационный индекс.

### R5. [HIGH] Убрать время из TRACE

- EXECUTION FLOW: убрать `[Self: 32ms]`, `[1552ms / 23ms]`
- CALL MAP / CALL INDEX: убрать `Budget: Xms`, `Total: Xms`
- MODULES: убрать колонки `Total` и `Pure` из строк событий
- Заголовки процедур в MODULES: убрать `Total: Xms Pure: Xms`

**Исключение:** можно оставить Total в заголовке процедуры MODULES в режиме FULL для справочной навигации, но с явной пометкой «справочно».

### R6. [MEDIUM] Очистить MODULES от фоновых модулей

В COMPACT: показывать только модули, связанные с основной цепочкой из EXECUTION FLOW.
В NORMAL: показывать модули из FLOW + первый уровень зависимостей.
В FULL: показывать всё.

**Конкретно для данного замера** в COMPACT должны остаться:
- M01 (форма ЭП), M02 (CryptoAPI), M03 (ОбщегоНазначения-крипто), M04 (ОбщегоНазначения), M05 (ВнешниеКомпоненты), Справочник.ВнешниеКомпоненты

**Убрать**: Сотрудники, РаботаСУведомлениями, ВстроеннаяПочтаСервер, РаботаСФайламиВызовСервера, РаботаСВиджетамиКлиент, РезервноеКопированиеИБ и т.д.

### R7. [MEDIUM] Убрать служебные параметры из TRACE META

Оставить:
```
=== TRACE META ===
format: TRACE v6
detail: compact
entry: all
block: all
```

Убрать: `flow_threshold_ms`, `modules_threshold_ms`, `flags` — перенести в TRACE REPRODUCE.

### R8. [LOW] Компактный формат TRACE COVERAGE

Текущий:
```
events_total=1535 events_shown=43 events_hidden=1492
call_map_total_entries=30 call_map_shown_entries=30 call_map_hidden_entries=0
modules_total_events=1535 modules_shown_events=334 modules_hidden_events=1201
structural_noise=202
...
```

Целевой:
```
=== TRACE COVERAGE ===
events: 43/1535 | call_map: 30/30 | modules: 334/1535
hidden: structural=202 control_leaf=108 trivial=12 tiny=566 repeats=0 callbacks=0 threshold=782
```
2 строки вместо 8.

## 10. ИТОГ

Формат TRACE v6 имеет серьёзные проблемы с эффективностью. **Более трети файла** — это повторяющиеся полные пути модулей в квадратных скобках. Три секции (FLOW, CALL MAP, MODULES) описывают одни и те же события, каждый раз повторяя полный путь. Слово `FACT` написано 365 раз в FULL, хотя оно предсказуемо по секции.

Ключевые изменения по приоритету:
1. **Алиасы модулей** — устраняют 30-36% overhead
2. **Компактные ссылки** `#ID` / `?ID` — устраняют синтаксический шум
3. **Удаление пустых `[свёрнуто]` строк** — устраняет информационный мусор
4. **CALL INDEX вместо CALL MAP** — устраняет дублирование секций
5. **Убрать время из TRACE** — убирает сотни паттернов, нарушающих принцип «TRACE ≠ PERF»
6. **Фильтрация фоновых модулей в COMPACT** — фокус на сценарий
