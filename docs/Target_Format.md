# Целевые форматы отчетов (Target Formats)

Спецификация форматов вывода парсера, оптимизированных для анализа LLM (Large Language Models). Основные цели: минимизация токенов, сохранение контекста, читаемость.

## 1. PFF TRACE (Хронологический лог)

Полный последовательный лог выполнения с восстановленной иерархией вызовов.

### Формат строки
```text
[Ctx] Level Location | Code [Stats]
```

- **[Ctx]**: Контекст выполнения.
  - `[C]`: Клиент
  - `[S]`: Сервер
  - `[C→S]`: Переход Клиент -> Сервер (вызов)
  - `[Bg]`: Фоновое задание
- **Level**: Визуальный отступ (2 пробела на уровень). Для LLM также можно дублировать числом `L0`, `L1`, но отступы экономичнее.
- **Location**: Местоположение кода.
  - Полный формат: `[Ext:Name] Module:Line`
  - Сокращенный (если модуль не менялся): `:Line`
  - `[Ext:Name]`: Имя расширения (только если код выполняется в расширении).
- **Code**: Текст исполняемого кода.
- **[Stats]**: Статистика выполнения.
  - `Nx`: Количество выполнений (если > 1).
  - `T:ms`: Total Time (время с вложенными вызовами).
  - `P:ms`: Pure Time (чистое время). Если `T ≈ P`, выводится только одно время.

### Пример

```text
=== PFF TRACE ===
Session: ThinClient #1563, Server #1563

[C] Обр.ОбработкаТест.Форма:29 | Сообщить("=== НАЧАЛО ТЕСТА PFF ===") 2.86ms
[C] :33 | Клиент.ВыполнитьКлиентскийКод() T:10.63 P:7.82ms
[C]   ОбщМод.Клиент:5 | Сообщить("Выполняется клиентский код") 1.01ms
[C]   :9 | Для Индекс = 1 По 1000 Цикл 1001x 0.58ms
[C]   :10 | Счетчик = Счетчик + 1 1000x 0.61ms
[C] :37 | КлиентСервер.ОбщийКод() T:3.61 P:3.33ms
[C]   ОбщМод.КлиентСервер:14 | ВспомогательнаяПроцедура() 0.09ms
[C→S] :41 | ТестНаСервере() T:96.90 P:15.85ms
[S]   [Ext:РасширениеТест] Обр.ОбработкаТест.Форма:8 | Сообщить("Выполняется ТестНаСервере") 0.02ms
[S]   :11 | Сервер.ВыполнитьСерверныйКод() T:9.25 P:0.02ms
[S]     ОбщМод.Сервер:6 | Сообщить("Выполняется серверный код") 0.01ms
```

### Правила сокращения
1. **Модуль**: Если текущая строка относится к тому же модулю и расширению, что и предыдущая (на том же уровне или родительском), имя модуля опускается, остается только `:НомерСтроки`.
2. **Время**:
   - Время < 0.01ms можно отображать как `0ms` или `<0.01ms`.
   - Если `Total` и `Pure` различаются менее чем на 1-5%, выводить только одно значение (просто `Xms`).

## 2. PFF PERF (Дерево производительности)

Агрегированное представление, сфокусированное на "тяжелых" вызовах.

### Структура
Дерево вызовов, где узлы с малым временем (`< Threshold`) свернуты.

### Пример
```text
=== PFF PERF (Threshold: 1.0ms) ===

[C→S] ТестНаСервере() | T:96.90ms (100%)
  [S] Сервер.ТестТранзакции() | T:87.92ms (90.7%)
    [S] ЗафиксироватьТранзакцию() | P:84.89ms (87.6%)
  [S] Сервер.ВыполнитьСерверныйКод() | T:9.25ms (9.5%)
    [S] ОбщМод.Сервер:13 (Цикл) | P:3.12ms (3.2%)
    [S] ОбщМод.Сервер:14 (Счетчик) | P:3.62ms (3.7%)
```

## 3. HOTSPOTS (Горячие точки)

Список строк кода, отсортированный по `Pure Time` (чистому времени выполнения). Позволяет мгновенно найти узкие места.

### Пример
```text
=== HOTSPOTS (Top 5) ===

1. [S] ЗафиксироватьТранзакцию()
   ОбщМод.Сервер:34 | P:84.89ms (66%) | 1x

2. [C] Клиент.ВыполнитьКлиентскийКод()
   Обр.ОбработкаТест.Форма:33 | P:7.82ms (6%) | 1x
   *Примечание: Высокий PureTime у вызова процедуры может указывать на накладные расходы или неучтенный код.*

3. [S] Счетчик = Счетчик + 1
   ОбщМод.Сервер:14 | P:3.62ms (2.8%) | 2000x
```

## Метаданные для LLM

В начало отчета добавляется компактная инструкция:

```text
Format: [Context] Module:Line | Code Stats
Context: [C]=Client, [S]=Server, [C->S]=Call to Server.
Stats: T=Total(with children), P=Pure(self).
Indent shows call stack.
```
