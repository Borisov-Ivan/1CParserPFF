# Целевой формат отчета TRACE (v3)

Документ описывает новый формат `TRACE`, ориентированный на надежную интерпретацию замеров PFF без эвристического восстановления дерева вызовов.

## Цели

- Сохранить максимум фактов из замера (код, строки, контекст, время, расширения).
- Уменьшить риск ложных связей между вызовами.
- Сделать вывод удобным для LLM: компактно, структурно, с явными подсказками для анализа.

## Ограничения исходных данных

- PFF обычно не содержит строк `Процедура Имя()` / `Функция Имя()`.
- В замере присутствуют маркеры конца: `КонецПроцедуры` / `КонецФункции`.
- Поэтому блоки идентифицируются диапазонами строк и типом блока, а не именем процедуры.

## Структура TRACE

`TRACE` состоит из трех секций:

1. `SUMMARY`
2. `CALL MAP`
3. `MODULES`

### 1) SUMMARY

Краткая сводка:

- `Events` — число событий.
- `Blocks` — число блоков замера (`block_id`).
- `Total` — общее время (сек).
- `Contexts` — список контекстов, встретившихся в замере (`[C]`, `[S]`, `[C→S]`, `[?]`).

Пример:

```text
=== SUMMARY ===
Events: 1361 | Blocks: 1 | Total: 1.57s
Contexts: [S]
```

### 2) CALL MAP

Список строк с заметным бюджетом вложенных вызовов.

- `Budget = Total - Pure`.
- Порог:
  - явный `threshold_ms`, если задан пользователем;
  - иначе `max(0.5ms, 1% от суммарного времени)`.

Для каждой строки выводится:

- контекст;
- модуль/строка;
- бюджет;
- фрагмент кода;
- опциональная подсказка `-> see: ...`, если найден подходящий блок из `MODULES` по модулю и времени.

Подсказка `-> see` **эвристическая**, не является гарантированной связью вызовов.

Пример:

```text
=== CALL MAP ===
Budget = Total - Pure (время, ушедшее во вложенные вызовы).

#1 [S] ВнешниеКомпонентыСлужебный:793 | Budget: 60.70ms
   Информация = ...СлужебныйВызовСервера.ИнформацияОСохраненнойКомпоненте(...)
   -> see: ВнешниеКомпонентыСлужебныйВызовСервера [S] Func(lines 45-89) [Total: 59.80ms]
```

### 3) MODULES

Сгруппированное представление по ключу:

- `Module`
- `Context`
- `Extension`

Внутри группы выводятся блоки:

- `[S] Func (lines X-Y)` — найден `КонецФункции`;
- `[C] Proc (lines X-Y)` — найден `КонецПроцедуры`;
- `[?] Block (lines X-Y)` — маркер конца не найден.

Для каждой строки блока:

- `:Line | Code  Total  Pure` (мс).

Пример:

```text
=== MODULES ===
--- ОбщийМодуль.ВнешниеКомпонентыСлужебный.Модуль ---

  [S] Func (lines 773-811) Total: 67.15ms Pure: 6.16ms
    :773 | Если ПараметрыПодключения = Неопределено Тогда   0.001  0.001
    :774 | ПараметрыПодключения = ...ПараметрыПодключения() 4.166  4.144
    ...
    :811 | КонецФункции                                      0.001  0.001
```

## Контекстные метки

- `[C]` — клиент
- `[S]` — сервер
- `[C→S]` — вызов сервера с клиента
- `[?]` — неизвестный/неподдержанный контекст

Контекст блока в `MODULES` задается в заголовке блока:

`[S] Func (lines X-Y)`

## Расширения

Если код выполняется в расширении, это всегда отмечается:

- заголовок модуля: `[Ext:ИмяРасширения] ...`
- в других секциях при необходимости.

## Что не входит в v3 TRACE

- Восстановление полного дерева вызовов (`CallTreeBuilder`) удалено как ненадежное.
- PERF-формат не меняется в этом этапе и анализируется отдельно.
