# Спецификация формата PFF (1C Performance File Format)

Документ описывает структуру файла замеров производительности 1С, восстановленную методом реверс-инжиниринга на основе эталонного замера `reference.pff`.

## Общая структура

Файл представляет собой текстовую сериализацию внутренних структур 1С (формат, похожий на сериализацию в `1cv8.pfl` или `ibases.v8i`, но с фигурными скобками).

Корневая структура:
```text
{Version, SessionCount, MeasurementGUID,
    SessionBlock1,
    SessionBlock2,
    ...
}
```

- `Version`: Версия формата (обычно `5`).
- `SessionCount`: Количество сессионных блоков (например, `2` для клиент-серверного вызова).
- `MeasurementGUID`: Уникальный идентификатор замера.

## Сессионный блок (Session Block)

Описывает сеанс, в котором происходило выполнение (Клиент, Сервер, Фоновое задание).

Пример:
```text
{10, "WS-HQ-43FAC", "", 1563, "", 32, "", AppGUID, SessionGUID, 3, UserGUID, Base64, UserGUID, "DefAlias"}
```

Ключевые поля (по индексам, начиная с 0):
- `0`: Тип записи (10 = Заголовок сеанса).
- `1`: Имя хоста (`"WS-HQ-43FAC"`).
- `3`: Номер сеанса (`1563`).
- `5`: Тип приложения:
  - `32`: Тонкий клиент (Thin Client).
  - `64`: Сервер (Server).
  - Возможны другие значения для Толстого клиента, Web-клиента и т.д.

Сразу за заголовком сеанса следует **Блок записей** (Record Block).

## Блок записей (Record Block)

Содержит список событий производительности для данного сеанса.

Пример:
```text
{0, 32, BlockGUID,
    Record1,
    Record2,
    ...
}
```

- `0`: Тип записи (0 = Блок данных).
- `1`: Количество записей в блоке (`32`).
- `2`: GUID блока (используется для связи записей с блоком).

## Структура записи (Record)

Каждая запись описывает одну строку исполняемого кода.

Пример (обычная запись):
```text
{
    {{"",0}, ModGUID, ConfGUID, 0, NullGUID, 0, Base64, ""},
    "ОбщийМодуль.Клиент.Модуль", 5, "Сообщить(""..."");",
    1, 0.0010115, 0.0010115, 0.78..., 0.78...,
    1, 0, 0, BlockGUID,
}
```

Пример (запись расширения):
```text
{
    {{"",0}, ModGUID, ConfGUID, 1, ExtGUID, 4, Base64, "РасширениеТест"},
    "РасширениеТест Обработка...", 8, "Сообщить(""..."");",
    1, 0.000021, 0.000021, 0.02..., 0.02...,
    0, 1, 0, BlockGUID,
}
```

### Поля записи

| Индекс | Имя | Тип | Описание |
| :--- | :--- | :--- | :--- |
| 0 | **Signature** | Struct | Блок идентификации кода (см. ниже). |
| 1 | **Module** | String | Полное имя модуля (например, `"ОбщийМодуль.Клиент.Модуль"`). |
| 2 | **Line** | Number | Номер строки кода. |
| 3 | **Code** | String | Текст исполняемой строки кода. |
| 4 | **Count** | Number | Количество выполнений данной строки (обычно 1, но для циклов может быть свернуто, хотя в reference.pff циклы развернуты). |
| 5 | **TotalTime** | Number | Время выполнения (включая вложенные вызовы), в секундах. |
| 6 | **PureTime** | Number | "Чистое" время выполнения (без вложенных вызовов), в секундах. |
| 7 | **TotalPct** | Number | Процент от общего времени (Total). |
| 8 | **PurePct** | Number | Процент от общего времени (Pure). |
| 9 | **ClientFlag** | 0/1 | Признак выполнения на Клиенте. |
| 10 | **ServerFlag** | 0/1 | Признак выполнения на Сервере. |
| 11 | **SrvProcFlag** | 0/1 | Признак "Обработка сервером" (обычно 1 при вызове сервера с клиента). |
| 12 | **BlockGUID** | GUID | Ссылка на GUID родительского блока записей. |

### Структура Signature (Поле 0)

Вложенная структура, описывающая метаданные исполняемого метода.

```text
{{"",0}, ModGUID, ConfGUID, ObjType, ExtGUID, ExtMethodType, Base64, "ExtName"}
```

| Индекс | Имя | Описание |
| :--- | :--- | :--- |
| 0 | - | Служебное поле `{"",0}`. |
| 1 | **ModGUID** | Уникальный идентификатор модуля. |
| 2 | **ConfGUID** | Идентификатор конфигурации. |
| 3 | **ObjType** | Тип объекта метаданных: <br> `0`: Общий модуль / Модуль объекта <br> `1`: Серверный метод формы? <br> `3`: Клиентский метод формы? |
| 4 | **ExtGUID** | GUID Расширения (или `0000...` если основная конфигурация). |
| 5 | **ExtMethodType** | Тип перехвата расширения: <br> `0`: Нет (Основная конфигурация) <br> `4`: `&Вместо` <br> Возможно `&Перед`/`&После` (требует уточнения). |
| 6 | - | Base64 данные (возможно, хэш или сигнатура). |
| 7 | **ExtName** | Имя расширения (пустая строка `""` для основной конфигурации). |

## Особенности интерпретации

1. **Иерархия вызовов:** В файле записи идут **плоским списком**, сгруппированным по модулям (а не хронологически!).
   - Пример: Сначала все строки `ОбщийМодуль.Клиент`, потом все строки `ОбщийМодуль.КлиентСервер`.
   - Для восстановления стека вызовов необходимо анализировать `TotalTime` vs `PureTime` и логические связи между модулями.

2. **Контекст:**
   - `(1, 0, 0)` -> **Клиент**
   - `(0, 1, 0)` -> **Сервер**
   - `(1, 0, 1)` -> **Клиент -> Сервер** (Вызов серверной процедуры с клиента). В этом месте происходит разрыв потока и переход в серверный блок.

3. **Расширения:**
   - Код расширений идентифицируется по непустому `ExtName` и `ExtGUID`.
   - Имя модуля может содержать префикс расширения (напр. `"РасширениеТест Обработка..."`), но надежнее смотреть в `Signature`.
